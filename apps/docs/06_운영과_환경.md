# 운영과 환경

이 문서는 현재 저장소에서 실제로 참고해야 하는 환경 변수, 부팅 방식, 운영 triage 순서, 실행 가능한 검증 명령을 정리한다.

## Source of Truth

- 운영 surface: `apps/api/app_factory.py`, `apps/api/runtime.py`, `apps/api/routes.py`
- 설정 owner: `apps/platform/settings.py`, `apps/planner/planner_defaults.py`
- 함께 읽을 문서: `04_회귀기준과_점검.md`, `06_API_응답명세.md`

## 운영 요약

| 항목 | 현재 기준 |
|---|---|
| 앱 조립 | `create_app()` |
| KV backend | Redis 우선, 실패 시 File KV fallback |
| 문서 기준 루트 | `apps/docs` |
| planner prompt asset | `apps/prompts/*` 절대경로 기준 |
| follow-up context truth | `SessionMemory.current_context`; 여기서 복원한 projection은 view-state-equivalent context로 취급 |
| debug route | `ENABLE_DEBUG_ROUTES=true`일 때만 `/query/debug` 활성 |
| 기본 pytest 실행 전제 | repo 루트 + `PYTHONPATH=.` |

## 주요 환경 변수

| 변수 | 설명 | 기본값/비고 |
|---|---|---|
| `NTIS_LOCAL_MODELS_ROOT` | 로컬 모델 자산 루트 | repo의 `Models` 또는 외부 경로 |
| `FILE_KVSTORE_ROOT` | File KV fallback 루트 | `local_kvstore` |
| `ENABLE_DEBUG_ROUTES` | `/query/debug` 활성화 | 기본 비활성 |
| `RAG_EVIDENCE_TOKEN_BUDGET` | evidence prompt 토큰 예산 | `20000` |
| `RAG_MIN_DENSE_SCORE` | dense 최소 score | `0.2` |
| `RAG_TOPK_DENSE` | dense top-k | `50` |
| `RAG_W_LEX` | lexical 가중치 | `0.4` |
| `RAG_TOPK_LEX_CAND` | lexical 후보 top-k | `100` |
| `RAG_OVERFLOW_QUEUE_SIZE` | overflow queue 크기 | optional |
| `RAG_CONTEXT_COMPRESS_MAX_DOCS` | context compression 대상 수 | optional |
| `LLM_DISAMBIGUATION_LABEL_ENABLED` | ADR-0014 Scope A 동명 후보 라벨 LLM enrichment 활성화 | 기본 비활성, 동일 라벨 잔존 시에만 LLM 호출 |
| `LLM_DISAMBIGUATION_LABEL_TIMEOUT_SECONDS` | Scope A labeler LLM 호출 timeout | 기본 `3.0`초 |
| `LLM_PROSE_ENABLED` | ADR-0014 Scope B clarification prose LLM paraphrase 활성화 | 기본 비활성, 실패 시 template seed fallback |
| `TURN_INTERPRETATION_LLM_FIRST` | ADR-0014 Scope C 후속 질문 해석 LLM-first 경로 활성화 | 기본 비활성, validator 실패 시 기존 heuristic fallback |

## 현재 권장 검증

### 1. 구문/부팅 smoke

```powershell
$env:PYTHONPATH='.'
python -m py_compile apps/api/app_factory.py apps/api/routes.py apps/conversation/request_facade.py apps/retrieval/retrieval_workflow.py apps/evidence/canonical_evidence.py apps/chat/answer_generation.py
python -m py_compile apps/conversation/clarification_labeler.py apps/conversation/turn_interpreter.py
python -c "from apps.api.app_factory import create_app; create_app()"
```

### 2. 현재 worktree에서 바로 실행 가능한 pytest subset

```powershell
python -m pytest tests/test_runtime_kv_fallback.py tests/test_settings_local_model_paths.py tests/test_platform_metrics.py -q -p no:cacheprovider
python -m pytest tests/test_answer_generation_reference_payloads.py tests/test_api_routes_reference_payloads.py tests/test_request_facade_child_detail_followup.py tests/test_lookup_join_hybrid_runtime_failure.py -q -p no:cacheprovider
python -m pytest tests/conversation/test_clarification_labeler.py tests/conversation/test_clarification_prose.py tests/conversation/test_turn_interpreter.py tests/test_request_facade_context_router.py -q -p no:cacheprovider
Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
```

### 3. 선택 검증

```powershell
$env:PYTHONPATH='.'
python -c "from apps.api.workflow_builder import build_request_workflow; build_request_workflow().compile()"
Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
```

- `langgraph`가 없는 환경에서는 workflow compile smoke를 생략한다.
- broad `pytest -q` 전체 수집 결과는 환경 의존성이 커서 운영 gate로 간주하지 않는다.
- validation truth는 이 문서와 `04_회귀기준과_점검.md`를 따른다.

## 운영 triage 순서

| 단계 | 로그/신호 | 확인 포인트 |
|---|---|---|
| 1 | `REQ.START` | 질문, conversation id, override 입력 |
| 2 | `PLANNER.SIGNALS`, `PLANNER.STAGE1`, `PLANNER.STAGE15`, `PLANNER.STAGE2`, `PLANNER.ASSEMBLE` | planner drift, ids_map, output_type |
| 3 | `RAG.RETRIEVAL_QUERY.RESOLUTION`, `RAG.RESULT`, `RAG.CONTEXT` | retrieval query, hit 수, canonical evidence 조립 |
| 4 | `LLM.RESULT`, `REQ.SUMMARY` | groundedness, answer-state consistency, degraded 여부 |
| 5 | startup 로그 | Redis 실패 시 file-store fallback 순서 |
| 6 | `RAG.LOOKUP_JOIN.HYBRID.RUNTIME_FAILURE` | lookup/join strict failure가 degraded answer로 surface되는지 |
| 7 | `DISAMBIGUATION.LABEL.ENRICHED` | 동명 후보 라벨 보강 전후 중복 수, `disambiguator_source`, `llm_attempted`, `reason`/`fallback_reason` |
| 8 | `CLARIFICATION.PROSE` | clarification 문구가 template/LLM/fallback 중 어느 경로로 합성됐는지 |
| 9 | `TURN.INTERPRETATION.LLM_FIRST` | LLM-first 해석의 validator 결과, 후보 수, `view_state`/`current_context` trigger |

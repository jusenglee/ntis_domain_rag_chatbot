## 핵심 요약

| 항목 | 기준 |
|---|---|
| `SEARCH / LOOKUP / JOIN` 의미 | 변경 금지 |
| planner 전략 truth | downstream 재결정 금지 |
| `pjt_id` / `pjt_no` | 혼용 금지 |

## 현재 실행 가능한 점검 명령

### 1. 필수 smoke

```powershell
$env:PYTHONPATH='.'
python -m py_compile apps/api/app_factory.py apps/api/routes.py apps/conversation/request_facade.py apps/retrieval/retrieval_workflow.py apps/conversation/view_state.py apps/chat/answer_generation.py
python -c "from apps.api.app_factory import create_app; create_app()"
```

### 2. 권장 pytest subset

```powershell
python -m pytest tests/test_runtime_kv_fallback.py tests/test_settings_local_model_paths.py tests/test_platform_metrics.py -q -p no:cacheprovider
python -m pytest tests/test_answer_generation_reference_payloads.py tests/test_api_routes_reference_payloads.py tests/test_request_facade_child_detail_followup.py tests/test_lookup_join_hybrid_runtime_failure.py -q -p no:cacheprovider
python -m pytest tests/conversation/test_clarification_labeler.py tests/conversation/test_clarification_prose.py tests/conversation/test_turn_interpreter.py tests/test_request_facade_context_router.py -q -p no:cacheprovider
Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
```

- repo 루트 기준 `pytest`는 현재 `PYTHONPATH=.`가 필요하다.
- broad rerun이나 전체 collect-only는 참고용일 뿐, current gate로 보지 않는다.

## 반드시 지킬 계약

| 계약 | 세부 규칙 |
|---|---|
| SEARCH | recall 우선, 사람/기관 hard must를 임의 추가하지 않는다 |
| LOOKUP / JOIN | precision 우선, server-side gate 유지 |
| planner ownership | `mode`, `relation`, `target_cols`, `join_key_mode`, count truth를 answer/retrieval stage에서 재생성하지 않는다 |
| follow-up truth | source reference, ordinal, child anchor, recent mention, visible manifest truth를 섞지 않는다 |
| identifier semantics | `pjt_id`, `pjt_no`, `rst_id`를 같은 축처럼 다루지 않는다 |
| evidence boundary | raw payload 전체나 retrieval metadata 전체를 prompt에 직접 넣지 않는다 |
| degraded behavior | strict failure를 숨기려고 fallback chat이나 mode rewrite를 하지 않는다 |

## 회귀 시나리오 체크리스트

### Route / reference

- invalid reference payload가 route 전체를 깨뜨리지 않고 fail-open으로 드롭되는지
- `/query/stream`이 `reference.set`과 `done`을 정상/오류/강등 종료 모두에서 유지하는지

### Follow-up / scope

- child detail follow-up에서 active scope truth가 유지되는지
- source reference나 ordinal follow-up이 planner 전략을 덮어쓰지 않는지
- `visible_answer_manifest`가 실제로 사용자에게 보인 목록의 truth만 소유하는지
- ADR-0014 follow-up gate가 `SessionMemory.current_context`를 공식 truth로 사용하고, projection은 view-state-equivalent context로만 쓰이는지
- 동명 clarification 후보 라벨이 raw payload 없이 `disambiguator`/`aux`로 구분되는지

### Retrieval / contract

- lookup/join hybrid runtime failure가 `INTERNAL_ERROR` 대신 strategy violation/degraded answer로 표면화되는지
- `pjt_id`와 `pjt_no`가 join/detail 흐름에서 섞이지 않는지

### 운영 환경

- Redis 실패 시 File KV fallback이 정상 동작하는지
- local model path와 metrics snapshot이 import/runtime smoke를 통과하는지

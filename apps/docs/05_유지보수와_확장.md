# 유지보수와 확장

이 문서는 현재 구조를 다시 무겁게 만들지 않기 위한 유지보수 규칙을 적는다.

## 핵심 요약
- feature owner는 `apps.planner`, `apps.conversation`, `apps.evidence`, `apps.retrieval`, `apps.chat`, `apps.platform`이다.
- workflow/service entrypoint는 callback/class 주입 대신 module import를 기본으로 한다.
- planner runtime defaults는 `apps/planner/planner_defaults.py`를 source-of-truth로 둔다.
- validation guidance가 바뀌면 운영/회귀 문서를 같은 change set에서 같이 갱신한다.

## 유지보수 규칙
- entrypoint 시그니처에는 실제 runtime input만 남긴다.
- `*_fn`, `*_cls`, `nodes`, `partial(...)`로 owner를 우회하는 조립 패턴을 다시 도입하지 않는다.
- planner / retrieval / chat 기본값을 `apps/api`나 임의 manifest로 다시 끌어올리지 않는다.
- retired validation entrypoint를 current README/runbook에 다시 올리지 않는다.

## 문서 동기화 규칙
- planner/runtime owner 변경: `README.md`, `03_운영과_환경.md`, `SESSION_HANDOFF.md`
- contract/strategy 변경: `02_실행계약과_전략규칙.md`, `04_회귀기준과_점검.md`
- large design decision: `apps/docs/ADR/`

## current debt
- dependency-complete 환경이 아니면 workflow graph smoke는 끝까지 못 돈다.
- worktree가 dirty한 동안에는 commit slicing 전 final cleanup 판단을 보수적으로 한다.
- historical pytest 기록은 남아 있어도 current validation guidance와 섞어 쓰지 않는다.

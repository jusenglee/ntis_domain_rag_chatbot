이 문서는 NTIS RAG를 `L1 의도 계약 + L2 행동안전 + Agentic front-controller` 구조로 정렬하기 위한 현재 완료 상태와 후속 작업을 기록한다.
완료된 tranche는 `[x]`, 앞으로 진행할 설계 드리프트 및 코드 리팩토링은 단계별 backlog로 정리한다.

## 현재 상태 요약

- `project LOOKUP/SEARCH/JOIN`, `people SEARCH`, `org SEARCH`, `perf SEARCH`는 모두 `ExecutionManager` ownership 아래 있다.
- `people/org/perf SEARCH`는 route-aware tool을 쓰되, `people/org/perf`별 target cols와 display rule을 유지한다.
- `JOIN` 자동 보정은 하나뿐이다.
  - `instance JOIN` 0건
  - active anchor의 `pjt_no` 존재
  - explicit instance axis lock 없음
  - 이때만 `group` retry 1회
- `support SEARCH`는 이번 캠페인에서 일부러 legacy로 남겼다.
- ADR-0001 Agentic Dialogue 전환을 시작했다.
  - `Conversation State Card`로 `SessionMemory.current_context`를 LLM 입력용 상태 카드로 투영한다.
  - `AgentDecision`은 `direct_answer`, `call_tool`, `ask_clarification`, `agent_internal_error`만 허용하며 old front-controller decision을 허용하지 않는다.
  - LLM 출력 parse/schema/tool validation 실패는 1회 self-repair 후 실패 시 `agent_internal_error`로 종료한다. 이 경로는 clarification으로 저장하지 않는다.
  - 1차 agent tool adapter는 `search_ntis_domain`, `refine_current_subject`, `ask_user_for_clarification`을 선언하고, 검색/refine은 guarded intent 생성까지 연결했다.
  - `lookup_specific_entity`는 manifest item lookup(`rank:N`/`title:[..]`/내부 ID) + bracket title recovery까지 실행 구현이 완료되었다 (`apps/conversation/agent_tool_executor.py`, `agent_tools.py`의 `implemented=True`).
  - `join_project_perf`는 여전히 선언만 있고 실행 미구현이다 (`agent_tools.py`의 `implemented=False`).

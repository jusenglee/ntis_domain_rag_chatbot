# 05 단계적 리팩토링 로드맵

이 문서는 NTIS RAG를 `L1 의도 계약 + L2 행동안전` 구조로 이관한 작업의 현재 완료 상태를 기록한다.
완료된 tranche는 `[x]`, 의도적으로 남겨둔 후속 backlog는 별도 섹션으로 정리한다.

---

## 완료된 단계

- [x] Phase 1: Atomic tool 추출 시작 (`project_tools`, `relation_tools`)
- [x] Phase 2: `RuntimeStrategyPolicy`, `ExecutionManager` 도입
- [x] Phase 3: `project LOOKUP`을 `ExecutionManager` 경로로 전환
- [x] Phase 4A: `project SEARCH` bounded recovery 전환
- [x] Phase 4D: runtime ownership / legacy retry boundary 정리
- [x] Phase 5A: `people SEARCH`, `org SEARCH` observation-first 전환
- [x] Phase 5B: `perf SEARCH` observation-first 전환
- [x] Phase 6: `JOIN` anchor 기반 group fallback 1회 도입
- [x] Phase 7: migrated head 기준 legacy cleanup 정리

---

## 현재 상태 요약

- `project LOOKUP/SEARCH/JOIN`, `people SEARCH`, `org SEARCH`, `perf SEARCH`는 모두 `ExecutionManager` ownership 아래 있다.
- `people/org/perf SEARCH`는 route-aware tool을 쓰되, `people/org/perf`별 target cols와 display rule을 유지한다.
- `JOIN` 자동 보정은 하나뿐이다.
  - `instance JOIN` 0건
  - active anchor의 `pjt_no` 존재
  - explicit instance axis lock 없음
  - 이때만 `group` retry 1회
- `support SEARCH`는 이번 캠페인에서 일부러 legacy로 남겼다.
- ADR-0001 Agentic Dialogue 전환을 시작했다.
  - `Conversation State Card`로 `SessionMemory.current_context`를 LLM 입력용 상태 카드로 투영한다.
  - `AgentDecision`은 `direct_answer`, `call_tool`, `ask_clarification`만 허용하며 legacy fallback decision을 허용하지 않는다.
  - 1차 agent tool adapter는 `search_ntis_domain`, `refine_current_subject`, `ask_user_for_clarification`을 선언하고, 검색/refine은 guarded intent 생성까지 연결했다.
  - `lookup_specific_entity`, `join_project_perf`는 선언만 있고 아직 실행 미구현이다.

## 완료 기준(DoD)

- [x] `perf SEARCH`가 `ExecutionManager`로 라우팅되고 `target_cols == [COL_PERF]`
- [x] `perf SEARCH`가 observation-only 1 step으로 끝남
- [x] `support SEARCH`는 여전히 legacy retriever로 남음
- [x] `JOIN instance` primary success 시 fallback 미실행
- [x] `JOIN instance` primary empty + `anchor_pjt_no` 존재 시 group fallback 1회 실행
- [x] explicit `pjt_id` / hard axis lock JOIN은 group fallback 차단
- [x] `anchor_pjt_no`가 없으면 empty + trace만 반환
- [x] `selected_answer_meta`는 summary only를 유지하고 full trace를 직접 노출하지 않음
- [x] dependency-complete 환경에서 full suite green

## 후속 backlog

이번 tranche 범위 밖이라 남겨둔 항목이다.

- `support SEARCH` 이관 여부 판단
- unsupported/deferred `JOIN`의 contract 정리
- legacy specialist flow 추가 정리
- 기존 workflow graph에서 `turn_trigger` / `turn_interpreter` / `turn_policy` front-controller 역할 제거
- agent tool executor를 retrieval / observation까지 확장
- `lookup_specific_entity`, `join_project_perf` 구현 후 legacy lookup/join 대화 경로 제거
- broader cleanup 이후의 운영/관측 지표 재정비

# 운영과 환경

이 문서는 현재 저장소 기준의 운영 triage 순서와 active validation 방식을 정리한다.

## 핵심 요약
- 현재 active validation은 `py_compile`, import smoke, `create_app()` smoke다.
- `scripts/run_baseline_checks.ps1`는 retired validation entrypoint다.
- `tests/` tree는 현재 worktree에서 active gate로 쓰지 않는다.
- planner runtime defaults의 source-of-truth는 `apps/planner/planner_defaults.py`다.

## 먼저 볼 것
- 로그: `REQ.START -> PLANNER.* -> RAG.* -> LLM.RESULT -> REQ.SUMMARY`
- planner defaults owner: `apps/planner/planner_defaults.py`
- app runtime owner: `apps/api/app_factory.py`, `apps/api/runtime.py`
- workflow owner: `apps/api/workflow_builder.py`, `apps/api/workflow_nodes.py`
- planner runtime owner: `apps/planner/planner_runtime.py`

## 현재 권장 검증
```powershell
python -m py_compile apps/api/app_factory.py apps/api/runtime.py apps/planner/query_analysis.py apps/planner/planner_runtime.py
python -c "import apps.planner.query_analysis, apps.planner.planner_runtime"
python -c "from apps.api.app_factory import create_app; create_app()"
```

- `langgraph`가 있으면 `build_request_workflow().compile()`까지 확인한다.
- `tests/`가 없는 현재 worktree에서는 pytest collect-only나 subset rerun을 current gate로 간주하지 않는다.
- retired script를 실행하면 clear failure로 멈추는 것이 정상이다.

## 운영 triage
1. `REQ.START`에서 raw query와 request override 입력을 확인한다.
2. `PLANNER.SIGNALS`, `PLANNER.STAGE1`, `PLANNER.STAGE15`, `PLANNER.STAGE2`, `PLANNER.ASSEMBLE` 순서로 planner drift를 본다.
3. `RAG.RETRIEVAL_QUERY.RESOLUTION`, `RAG.RESULT`, `RAG.CONTEXT`에서 retrieval/evidence 흐름을 확인한다.
4. `LLM.RESULT`와 `REQ.SUMMARY`에서 answer selection, groundedness, state consistency를 확인한다.

## 문서 갱신 규칙
- planner defaults owner가 바뀌면 이 문서와 `README.md`, `04_회귀기준과_점검.md`, `SESSION_HANDOFF.md`를 같이 갱신한다.
- streaming/debug payload shape가 바뀌면 이 문서와 `02_실행계약과_전략규칙.md`를 같이 갱신한다.
- retired validation entrypoint를 다시 활성화하지 않는 한, baseline script나 manifest-driven pytest를 current guidance에 다시 넣지 않는다.

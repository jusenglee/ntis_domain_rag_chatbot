# 유지보수와 확장

이 문서는 현재 구조를 무겁게 되돌리지 않고, 코드와 문서를 함께 유지하기 위한 규칙을 정리한다.

## Source of Truth

- 패키지 구조와 흐름: `01_아키텍처와_흐름.md`
- 계약: `02_실행계약과_전략규칙.md`
- 운영/회귀: `03_운영과_환경.md`, `04_회귀기준과_점검.md`

## 핵심 원칙

| 항목 | 원칙 |
|---|---|
| feature owner | `apps.api`, `apps.conversation`, `apps.planner`, `apps.retrieval`, `apps.evidence`, `apps.chat`, `apps.platform` |
| entrypoint | 현재 feature package owner를 우회하는 임시 조립 레이어를 늘리지 않는다 |
| defaults owner | planner/runtime/chat 기본값은 owner 모듈에 둔다 |
| 문서 동기화 | 사용자-visible 계약이 바뀌면 코어 문서를 같은 change set에서 같이 고친다 |

## 유지보수 규칙

### 코드 구조

- entrypoint 시그니처에는 실제 runtime input만 남긴다.
- `*_fn`, `*_cls`, 임의 callback 주입, 우회 manifest로 owner를 분산시키지 않는다.
- planner/retrieval/evidence/chat 책임 경계를 흐리는 broad rewrite를 피한다.

### 계약 변경

- `mode`, `relation`, `join_key_mode`, `output_type`, identifier semantics가 바뀌면 문서와 테스트를 함께 갱신한다.
- raw -> canonical -> prompt 흐름을 우회하는 편법을 추가하지 않는다.
- `pjt_id`, `pjt_no`, 기관 역할, child subject 축은 기존 의미를 유지한 채 확장한다.

### 검증과 기록

- validation guidance가 바뀌면 `03_운영과_환경.md`, `04_회귀기준과_점검.md`를 같이 갱신한다.
- 대형 설계 결정은 `apps/docs/ADR/`에 남긴다.
- 작업 이력과 남은 리스크는 `SESSION_HANDOFF.md`에 append한다.

## 기술 부채와 확장 주의점

| 항목 | 현재 상태 |
|---|---|
| workflow compile smoke | optional dependency가 없는 환경에서는 생략될 수 있음 |
| pytest lane | repo 루트 기준 `PYTHONPATH=.` 전제가 필요함 |
| historical 문서 | `SESSION_HANDOFF.md`, watcher report는 현행 source of truth가 아님 |
| docs drift | stale 경로와 실행 명령이 다시 생기지 않도록 코어 문서를 우선 갱신해야 함 |

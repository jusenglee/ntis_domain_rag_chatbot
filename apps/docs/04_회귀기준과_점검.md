# 회귀기준과 점검

이 문서는 현재 저장소에서 어떤 계약을 계속 지켜야 하는지와, 지금 실제로 돌릴 수 있는 점검 방법을 적는다.

## 핵심 요약
- SEARCH / LOOKUP / JOIN 의미는 바꾸지 않는다.
- planner 전략은 answer stage에서 다시 결정하지 않는다.
- follow-up anchor truth, `pjt_id` / `pjt_no` 분리, canonical evidence 경계는 그대로 유지한다.
- 현재 worktree의 active regression gate는 smoke 검증이다.

## 현재 점검 명령
```powershell
python -m py_compile apps/api/app_factory.py apps/api/runtime.py apps/planner/query_analysis.py apps/planner/planner_runtime.py
python -c "import apps.planner.query_analysis, apps.planner.planner_runtime"
python -c "from apps.api.app_factory import create_app; create_app()"
```

## optional smoke
```powershell
python -c "from apps.api.workflow_builder import build_request_workflow; build_request_workflow().compile()"
```

- 위 명령은 `langgraph`가 있는 환경에서만 기대한다.
- `tests/`가 현재 worktree에 없으므로 pytest 파일 경로를 current checklist에 쓰지 않는다.

## 반드시 지킬 계약
- SEARCH는 recall 우선이다. server-side must를 넣지 않는다.
- LOOKUP / JOIN은 정확도 우선이다. server-side gate를 유지한다.
- 사람/기관 질의는 기본적으로 LOOKUP으로 다룬다.
- BM25-only 우회는 금지한다.
- fallback chat, mode 변경, 재시도성 전략 변경은 금지한다.
- 근거가 약하면 보수적으로 답한다.

## 회귀를 볼 때 확인할 것
- planner: `PLANNER.SIGNALS`, `PLANNER.STAGE1`, `PLANNER.STAGE15`, `PLANNER.STAGE2`, `PLANNER.ASSEMBLE`
- retrieval: `RAG.RETRIEVAL_QUERY.RESOLUTION`, `RAG.RESULT`, `RAG.CONTEXT`
- answer: `LLM.RESULT`, `REQ.SUMMARY`
- follow-up: source reference, child anchor, active scope truth가 retrieval query를 임의로 덮지 않는지

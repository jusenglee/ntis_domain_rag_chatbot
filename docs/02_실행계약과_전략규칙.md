# 실행 계약과 전략 규칙

이 문서는 현재 NTIS Domain RAG의 실행 계약 정본이다.

## Retrieval Intent Contract

- planner는 질의마다 하나의 retrieval intent를 확정한다.
- executor는 planner가 확정한 artifact를 검증하고 실행하지만, 새로운 SEARCH / LOOKUP / JOIN 전략을 발명하지 않는다.
- `IntentPayloadV3`는 활성 transport 계약이다.
- `QuestionAnalysis v3 / IntentPayloadV3` 조합이 v3 baseline이다.

## Strategy Assembly Contract

### Stage 1
- `action`
- `head`
- `relation_candidate`
- `referential_followup`
- `confidence`

Stage 1은 `mode`, `join_key_mode`, `target_cols`, `ids_map`, `candidate_keys`, `filters`를 확정하지 않는다.

### Deterministic gate
- deterministic gate artifact는 `mode`, `action`, `relation`, `join_key_mode`, `target_cols`, `output_type`를 고정한다.
- gate join mode는 `instance | group`만 허용한다.
- gate artifact에는 `deferred`를 넣지 않는다.

### Assembled question analysis
- assembled question analysis는 Stage 2 slot과 sanitize 결과를 merge한 artifact다.
- `candidate_keys.project_key`
- `project_key_policy`
- `join_resolution_policy`
- `ids_map`
- `filters`
- `retrieval_query`
- `limit`

ambiguous exact project key는 assembly에서 `join_key_mode=deferred`로 legalize할 수 있다.
이 경로는 fallback이 아니라 assembly legalize다.

## Runtime Enforcement Contract

- `SEARCH`, `LOOKUP`, `JOIN`은 서로 다른 계약이다.
- `ids_map`에는 resolved identifier만 들어간다.
- `candidate_keys.project_key`는 unresolved exact project key다.
- `project_key_policy=ambiguous_or`는 exact OR exact discovery다.
- `join_key_mode=deferred`는 assembled/runtime에서만 합법이다.
- `dual_branch_used`는 runtime observability 필드다.
- `resolved_join_key_mode`는 runtime 산출물이다.

### join_key_mode
- `instance`: resolved `pjt_id` 기반 strict mode
- `group`: resolved `pjt_no` 기반 strict mode
- `deferred`: ambiguous exact project key 기반 runtime discovery mode

### no-result policy
- `lookup` + `reason=no_reranked` -> `normal_no_result`
- `join` + `reason=no_reranked` -> `normal_no_result`
- `search` + `reason=no_reranked` remains `strict_search`

### 의미 불변식
- `pjt_id`는 instance key다.
- `pjt_no`는 group key다.
- `pjt_id != pjt_no`
- `lead_org_name`, `participant_org_name`, `people_affiliation_org_name`은 서로 다른 역할 필드다.

## Extended Runtime

- `comparison`
- `series`
- `perf_to_project_to_perf`
- `pattern_analysis`
- `multi_hop_bundle`
- `anchor_resolution`

## 운영 용어 정리

- strategy fallback: 금지 대상. lower layer가 새 전략을 만드는 것.
- assembly legalize: 허용 대상. ambiguous project key를 deferred로 합법화하는 것.
- response fallback: 허용 대상. stream fallback, answer fallback, embedding fallback 등.
